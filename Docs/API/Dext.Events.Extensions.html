record TEventBusDIExtensions

PUBLIC
function AddEventBus: TDextServices
Registers IEventBus as a SINGLETON. Each Publish call creates a fresh DI scope, isolating handlers from each other and from the caller. Call before AddEventHandler / AddEventBehavior.
function AddScopedEventBus: TDextServices
Registers IEventBus as a SCOPED service. Publish uses the current DI scope (injected at construction time) so handlers share the same unit-of-work as the code that published the event. Ideal for HTTP request handlers where you want handlers to participate in the same DbContext transaction. Call before AddEventHandler / AddEventBehavior.
function AddEventHandler<TEvent,THandler>: TDextServices
Registers THandler as a handler for event type TEvent. Multiple handlers per event type are supported - they run in order. THandler is resolved from the DI scope per Publish call.
function AddEventBehavior<TBehavior>: TDextServices
Registers TBehavior as a GLOBAL pipeline behavior (all event types). First registered = outermost in the pipeline. TBehavior is resolved from the DI scope per Publish call.
function AddEventBehaviorFor<TEvent,TBehavior>: TDextServices
Registers TBehavior as a PER-EVENT pipeline behavior for TEvent only. Per-event behaviors run INSIDE global behaviors (closer to the handler). TBehavior is resolved from the DI scope per Publish call. Note: named AddEventBehaviorFor (not AddEventBehavior) to avoid an "Ambiguous overloaded call" error in Delphi 11/12 - the compiler cannot disambiguate generic overloads that differ only in type- parameter count on record helpers.
function AddEventPublisher<T>: TDextServices
Registers IEventPublisher as a transient service. Components that only ever publish one event type can inject the narrow IEventPublisher instead of IEventBus - clearer intent and easier to mock in unit tests. Usage: Services .AddEventBus .AddEventHandler .AddEventPublisher; // Then inject: constructor TOrderService.Create( const APublisher: IEventPublisher);
function AddEventBusLifecycle: TDextServices
Registers TEventBusLifecycleService as a singleton IHostedService and sets up a IHostedServiceManager to start/stop it automatically. Prerequisites: - IEventBus must already be registered (call AddEventBus or AddScopedEventBus first). - IHostApplicationLifetime must be registered (the web host registers it automatically; for console apps use AddHostApplicationLifetime). Note: if your application already calls AddBackgroundServices/Build, add TEventBusLifecycleService to that builder and skip this method to avoid registering a second IHostedServiceManager.
